# 悅讀免費 TTS API 選型建議

## 背景

目前「悅讀」的語音朗讀使用瀏覽器內建 Web Speech API。這種方式免費、容易實作，但聲音品質取決於學生的瀏覽器與作業系統，常見問題是聲音偏機器人、音色選擇少，且很難穩定提供男聲、女聲、小朋友聲或不同情緒音色。

若要提供自然人聲朗讀，需要改成「後端呼叫 TTS 服務，前端播放產生的音訊」。

## 免費或可免費開始的選項

### 1. Microsoft Edge TTS（推薦先做 MVP）

優點：

- 免費使用門檻低。
- 中文聲音自然度通常比瀏覽器內建朗讀好。
- 可選多種中文神經語音，例如女聲、男聲、少年感聲音。
- 適合先做學校內部測試或 MVP。

常見中文聲音：

- `zh-CN-XiaoxiaoNeural`：女聲，溫柔、標準。
- `zh-CN-XiaoyiNeural`：女聲，較甜美。
- `zh-CN-YunxiNeural`：男聲，清亮、年輕。
- `zh-CN-YunyangNeural`：男聲，穩定、播報感。

缺點：

- 不是官方商業 API。
- 長期穩定性與使用條款有不確定性。
- 大量正式教學使用時，可能遇到限制或服務變動。

結論：

- 適合「先免費試自然人聲」。
- 不建議把它當成長期唯一正式方案。

### 2. FreeTTS 類免費 API

優點：

- 有些服務提供免費 REST API。
- 可能不需要 API key。
- 接入速度快，適合快速比較音色。

缺點：

- 免費服務穩定性不一定高。
- 額度、速度、可用聲音可能隨時變動。
- 不一定適合正式課堂大量使用。

結論：

- 可作為備選測試，不建議作為正式主方案。

### 3. Google Cloud TTS / Azure Speech

優點：

- 官方服務，穩定性高。
- 中文聲音品質好。
- 適合正式產品與長期使用。

缺點：

- 免費通常是新戶試用額度或有限免費額度。
- 超過額度後會按字數計費。

結論：

- 適合正式上線後使用。
- 若學生數量增加，建議逐步轉向這類官方 TTS。

### 4. ElevenLabs

優點：

- 聲音自然度高。
- 多語言支援中文。
- 適合展示高品質朗讀效果。

缺點：

- 免費額度有限。
- API 免費帳號可能有較多限制。
- 中文大量朗讀成本需要控制。

結論：

- 適合展示或高品質場景。
- 不一定是最省錢的教學朗讀方案。

## 推薦路線

第一版建議採用：

**Microsoft Edge TTS 作為免費自然人聲 MVP，保留瀏覽器內建朗讀作 fallback。**

原因：

- 成本最低。
- 中文聲音可用性高。
- 可以快速驗證學生是否真的常用自然人聲朗讀。
- 若 Edge TTS 失敗，仍可退回原本的瀏覽器朗讀，不會影響基本功能。

正式長期版本建議：

**MiniMax TTS / Azure Speech / Google Cloud TTS**

原因：

- 更穩定。
- 商業使用與服務條款更清楚。
- 適合大量學生長期使用。

## 建議功能設計

前端在文章頁新增「自然人聲朗讀」區塊：

- 聲音選單：
  - 女聲
  - 男聲
  - 少年聲
  - 溫柔聲
  - 活潑聲
- 語速選擇：
  - `0.8x`
  - `1x`
  - `1.2x`
- 按鈕：
  - `自然人聲朗讀`
  - `停止播放`
- 狀態提示：
  - `正在生成語音...`
  - `生成完成`
  - `自然人聲失敗，已改用瀏覽器朗讀`

後端新增：

- `enjoyread/app/api/tts/route.ts`

請求格式可設計為：

```json
{
  "text": "要朗讀的精華短文",
  "voice": "zh-CN-XiaoxiaoNeural",
  "speed": 1
}
```

回傳：

- 成功：`audio/mpeg` 或 base64 音訊。
- 失敗：JSON 錯誤訊息，前端 fallback 到 Web Speech API。

## 成本控制建議

即使第一版使用免費方案，也建議先建立成本控制習慣：

- 只朗讀「精華短文」，不要朗讀整篇原文。
- 限制單次朗讀文字長度，例如最多 800 字。
- 同一篇文章、同一聲音、同一語速可快取音訊。
- 若未來接付費 TTS，加入每日使用次數上限。
- 出錯時退回瀏覽器內建朗讀。

## 與悅讀現有架構的接入點

目前朗讀邏輯在：

- `enjoyread/app/article/page.tsx`

目前使用：

```ts
const utterance = new SpeechSynthesisUtterance(summary);
```

第一版改造方向：

- 保留這段作 fallback。
- 新增自然人聲播放流程：
  1. 前端送 `summary + voice + speed` 到 `/api/tts`
  2. 後端產生音訊
  3. 前端用 `Audio` 或 `<audio>` 播放
  4. 失敗時呼叫原本 `SpeechSynthesisUtterance`

## 最終建議

短期：

- 用 Microsoft Edge TTS 做免費 MVP。
- 提供 4-5 種中文聲音。
- 保留瀏覽器朗讀 fallback。

中期：

- 觀察學生使用量。
- 加入快取與使用次數限制。

長期：

- 若使用穩定且學生數量增加，改接 MiniMax、Azure 或 Google Cloud TTS 作正式方案。
